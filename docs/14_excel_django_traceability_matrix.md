# Bidirectional Excel-Django Traceability Matrix

**Version:** 0819.0810  
**Project:** STH Freight Calculator  
**Purpose:** Support rapid lookup from an Excel element, web screen, Django Admin section, model, importer or calculation-engine component.

## How to use this matrix

- Search by `trace_id` for a stable reference.
- Filter by `excel_source` when the question begins with a worksheet or cell.
- Filter by `django_admin` or `model_field` when the question begins in the application.
- Before changing logic, review `evidence_status`, `validation` and `risk_notes`.
- Keep the same `trace_id` even when visible names or internal paths change.

## Evidence states

- `CONFIRMED`: supported by current code and existing documentation or tests.
- `PARTIAL`: the code relationship is confirmed, but it still requires isolation or verification of the exact Excel formula.
- `PENDING_EXCEL`: must not be treated as complete without inspecting the workbook and creating an Excel-vs-Django case.
- `REVIEW_RISK`: current behaviour may contain a gap or incomplete implementation.
- `CURRENTLY_UNUSED`: stored or transmitted, but not queried by the current engine.
- `WEB_ONLY`: application-specific requirement with no direct functional Excel equivalent.

## Evidence basis for this version

This version was reconciled against the updated code and `V2026.R2_Unlocked_STH_Freight_Calculator.xlsx`. Rows marked `PARTIAL`, `PENDING_EXCEL` or `REVIEW_RISK` identify rules that still require a targeted test; they do not indicate that the workbook is unavailable.
