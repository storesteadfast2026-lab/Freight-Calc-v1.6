# Matriz bidireccional de trazabilidad Excel–Django

**Versión:** 0722.1350  
**Proyecto:** STH Freight Calculator  
**Propósito:** permitir búsquedas rápidas desde cualquier elemento del Excel, la pantalla web, Django Admin, los modelos, el importador o el motor de cálculo.

## Cómo usarla

- Busca por `trace_id` para una referencia estable.
- Filtra por `origen_excel` cuando la pregunta comienza en una hoja/celda.
- Filtra por `django_admin` o `modelo_campo` cuando la pregunta comienza en la aplicación.
- Antes de cambiar lógica, revisa `estado_evidencia`, `validacion` y `notas_riesgos`.
- Mantén el mismo `trace_id` aunque cambien nombres visibles o rutas internas.

## Estados de evidencia

- `CONFIRMADO`: respaldado por código y documentación/pruebas existentes.
- `PARCIAL`: relación confirmada en código, pero falta aislarla o verificar fórmula exacta en Excel.
- `PENDIENTE_EXCEL`: no debe considerarse cerrada sin inspeccionar el workbook y crear caso Excel vs Django.
- `RIESGO_REVISAR`: el comportamiento actual presenta una posible brecha o implementación incompleta.
- `NO_USADO_ACTUALMENTE`: se almacena o transmite, pero el motor actual no lo consulta.
- `WEB_ONLY`: requisito propio de la aplicación, sin equivalente funcional directo en Excel.

## Base de evidencia de esta versión

Esta versión fue contrastada con el código actualizado y con `V2026.R2_Unlocked_STH_Freight_Calculator.xlsx`. Las filas marcadas `PARCIAL`, `PENDIENTE_EXCEL` o `RIESGO_REVISAR` continúan indicando reglas que requieren una prueba dirigida, no ausencia del workbook.
